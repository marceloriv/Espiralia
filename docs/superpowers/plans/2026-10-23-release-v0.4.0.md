# Release v0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dejar `feature/stitch-visual-fidelity` lista para publicar como `v0.4.0` en GitHub Pages: cerrar el hueco funcional de borrado de perfil, limpiar textos, alinear la documentación y los gates con la realidad, y ejecutar el flujo Git Flow de release.

**Architecture:** Cambios pequeños y aislados, uno por commit. El borrado de perfil reutiliza `StorageService.deleteProfile` (ya probado) y `verifyPin`, y se expone solo en `ProfileSettingsModal`; el cierre de sesión posterior reutiliza `onLockProfile`, sin nuevas props en `App`, `AppRoutes` ni `ProtectedRoute`. La publicación sigue AGENTS §11.3.

**Tech Stack:** TypeScript 5.8, React 19.2, Vite 6.4, Vitest, pnpm 10, GitHub Actions + Pages.

**Spec:** `AGENTS.md` (§7 pruebas, §9 QA, §10 seguridad, §11 commits y ramas, §12 límites, §13 deploy, §17 normativa) y el informe de verificación funcional del 2026-10-23 (conversación). No hay documento de diseño aparte.

## Global Constraints

- Commits: `:emoji: tipo(alcance): sujeto` en español, minúsculas, imperativo, sin punto final, máximo 72 caracteres. Alcances permitidos: `layout`, `agenda`, `planner`, `tareas`, `dashboard`, `perfiles`, `storage`, `routes`, `config`, `test`.
- Sin firma de agente en commits ni en descripciones de PR (AGENTS §11.1).
- Pruebas solo en `src/tests/`. Comando acotado: `pnpm exec vitest run src/tests/<archivo>`.
- Nunca renombrar claves de `localStorage` ni cambiar formas guardadas. `src/tests/legacyDataCompat.test.tsx` debe seguir en verde.
- Controles interactivos de al menos 44x44px (`--tap-min`). Sin emojis en la interfaz (`antislopNoEmoji.test.ts`). Idioma de la interfaz: español.
- Requieren aprobación explícita del dueño antes de ejecutarse: editar `.github/workflows/*`, agregar dependencias, `git push`, abrir PR, crear tags, desplegar (AGENTS §12).
- Un feature se integra a `develop` solo por PR; nunca merge directo local.

## Review Focus

Entradas y condiciones que el spec implica y que ninguna tarea de abajo debe dejar sin prueba:

1. Borrar un perfil cuando existe otro: los datos del otro perfil quedan intactos (Task 3).
2. PIN vacío o erróneo al borrar un perfil protegido: no se borra nada (Task 3).
3. Nombre de confirmación con espacios alrededor: se acepta tras `trim()`; con distinta capitalización no se acepta (Task 3).
4. Borrar el único perfil: la app vuelve a `#/login` con "Crea un perfil para empezar." y una recarga no lo resucita (Task 3).
5. Cambios de copy: los guardianes `antislopCopy`, `antislopHonestClaims` y `emptyProfileMetrics` siguen en verde (Task 4).
